# cmdbuf_rd 容量隔离修订

用户新增约束：在满足输入输出约束时，不能让一个 XAU 占满所有 entry，导致其他 XAU 无法发送命令。该要求覆盖原“九项无准入保护共享”的规则；CMDBUF 和 OTB 的九项物理池、一一对应和 R 返回后释放规则保持。

采用每个 XAU 逻辑保留一项、其余六项共享的设计。保底一项是满足入口资源可用性的最小方案，并非用户另行指定的配额数字。不按物理编号将存储切成三块；同一分配器选择可用 entry。

## 占用与准入

occ[x] 统计来源 x 的全部已接收、未完成 R 返回的命令，包含已发射和 MEM 已完成但尚未返回上游的命令。只有 R 退休才扣除占用。

保持不变量：

```text
sum(max(occ[x], 1)) <= 9
等价于 sum(max(occ[x] - 1, 0)) <= 6
```

单个 XAU 因而最多使用七项。仅添加“每路至多七项”仍不够，(4,5,0) 会把第三路挡住；上述不变量同时禁止两路用满全部容量。

兼容 10B 的准入伪代码：

```text
retire[x] = rvalid[x] && rready[x]
occ_after[x] = occ[x] - retire[x]
free_after = 9 - sum(occ_after)
shared_after = sum(max(occ_after[x] - 1, 0))
arready[x] = (free_after > 0)
          && ((occ_after[x] == 0) || (shared_after < 6))
accept[x] = arvalid && (src == x) && arready[x]
occ_next[x] = occ_after[x] + accept[x]
```

retire 由已有命令的 R 响应产生，不能反过来依赖新 AR 分配。物理空位仍使用 `~valid | retire_mask`。同拍退休复用时 R 读取旧负载，沿后新分配初始化覆盖旧归属清除。

当来源 x 为零占用时，不变量必然为它留有空槽；它接收首条命令不增加 max(occ[x],1)。因此即使其他来源长期不退休，它仍有至少一条接收资格。

| 占用 (XAU0,XAU1,XAU2) | 当拍退休 | arready[2:0] |
| --- | --- | --- |
| (7,0,0) | 无 | 110 |
| (7,1,0) | 无 | 100 |
| (7,1,1) | 无 | 000 |
| (4,4,0) | 无 | 100 |
| (7,1,1) | XAU1 的唯一命令 | 010 |
| (7,1,1) | XAU0 的一条命令 | 111 |

## 保证范围

用户已确认上游可以切换 src，但公平性未定。cmdbuf_rd 保证空位及对应 ready；一组共享 AR 每拍仍只能接收一条，模块不能强迫上游为另一来源提供发送机会。因此目前不建立“任意持续请求最终一定被接收”的无条件活性断言。

零占用来源有首条准入资格，不等于每个来源都始终有资格追加第二条。五项乱序窗口也保持：其他来源使用保底接收的第六条命令仍可能在窗口外等待，不能以容量公平为由越窗发射。

本策略会使只有一个来源活动时，最多占用七项，另外两项保留；这是保证其他来源后来到达时仍有空位的容量代价。
